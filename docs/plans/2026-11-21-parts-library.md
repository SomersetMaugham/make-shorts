## 1. 현재 문제

- PN 3편: `gfx_s3b.py`가 자체 `drawBattery`를 만들어 같은 편 `gfx_s3a.py`(`S.battery`)와 다른 건전지가 나왔다. 전류계·전압계는
  키트에 없어 매번 손으로 조합했다. 3편 그래픽 파일 3개의 원시 호출(`S.line/path/rect/circle`)은 166·171·72개.
- 크기 기준이 없다(`s` 1, 1.15 …). seed가 전역 `seed++`(sketch.js:38)라 그리는 순서와 좌표에 따라 모양이 바뀐다.
- **이미 있는 버그(리뷰에서 발견, Claude 확인):** `prep()`(sketch.js:238)이 모든 선에 `strokeDasharray = "L L"`을 덮어써서
  rough.js의 `strokeLineDash`가 사라진다. `S.hole`(점선 원), `S.band`, `S.chair({empty})`가 점선이 아니라 실선으로 나온다.

## 2. 핵심 설계

1. **정규 좌표계.** 부품마다 원점 중심·가로 방향·고정 크기로 한 번만 정의한다(`defPart(name, spec)`).
   몸통 길이 **120 px(1 유닛)**, 2단자 핀은 `(-60,0)`/`(60,0)`. 3단자 이상은 정의된 핀 위치(모두 20 px 격자 위).
2. **고정 seed.** 획 i의 seed = `base(name) + 16·i`, `base = (hash(name) >>> 0) % 2147483000 + 1`.
   - 0이면 rough.js가 `Math.random()`으로 바뀌므로(`class p`) **항상 1 이상**으로 둔다.
   - rough.js는 이중 획에 `seed+1`을 쓰므로(`function z`) 획끼리 간격을 16씩 둔다.
   - 부품 안에서는 `S.o`의 전역 `seed++`를 쓰지 않는다(누락 방지를 위해 부품 빌더가 seed를 직접 주입).
   - `fillStyle: 'dots'`는 내부에서 `Math.random()`을 써서 금지한다.
3. **배치는 SVG 변환.** `<g transform="translate(x y) rotate(θ) scale(k)">`에 정규 도형을 넣는다. rough.js에 들어가는 좌표가
   늘 같으므로 `path d`가 같다. 회전은 0/90/180/270 기본, 좌우 반전 `flip` 허용.
4. **크기 3단계 = 격자에 맞는 배율.** `S` 2/3(몸통 80) · `M` 1(120) · `L` 4/3(160). 반길이 40/60/80 px가 모두 20 px 격자 위에 온다.
5. **굵기 보정은 생성 뒤 DOM에서.** rough.js는 늘 같은 옵션(굵기 5/8/4.5, `hachureGap`·`fillWeight` 명시)으로 생성하고,
   만든 `<path>`의 `stroke-width`만 `굵기 ÷ k`로 바꾼다. 화면 굵기가 크기와 상관없이 전선과 같고, 카메라 푸시 때는 함께 커진다.
   `vector-effect: non-scaling-stroke`는 카메라 확대까지 상쇄하므로 쓰지 않는다.
6. **글자는 변환 그룹 밖에 둔다.** `+`/`−`, `A`/`V`, `M`, 핀 이름, 라벨은 부품 변환으로 위치만 계산해 **월드 좌표에 회전 0으로** 쓴다.
   그래서 세로 부품의 글자가 눕지 않고, 쓰기 방향도 뒤집히지 않으며, `prep()`의 페이지 이탈 보정(sketch.js:224-231)도 정상 동작한다.
7. **해칭 채우기.** 부품 안의 해칭은 부품 기준 각도로 고정한다(회전하면 같이 돈다 = 같은 모양). 크기별 간격은 원래대로 유지하고
   굵기만 5번처럼 보정한다.
8. **단자 접합.** 부품 리드 끝점은 `preserveVertices: true`로 정확히 핀에 떨어지게 하고, 바깥 전선은 핀에서 시작한다.
9. **반환값 통일.** 모든 부품은 월드 좌표로 계산한 다음 값을 돌려준다(행렬을 JS로 직접 곱한다. DOM `getBBox`/`getCTM`은 쓰지 않는다):
   `{ pins: {…}, path: [...], paths: {…}, box: {x,y,w,h}, at(t, state) }`.
   - 핀 이름 규약: 무극성 `A`/`B`, 유극성 `P`(+)/`N`(−), 다이오드류 `A`/`K`, BJT `B`/`C`/`E`, MOSFET `G`/`D`/`S`,
     연산증폭기 `INP`/`INN`/`OUT`(+ 전원 `VP`/`VN`), 변압기 `P1 P2 S1 S2`, 스위치 `A`/`B`(SPDT는 `COM`/`NO`/`NC`).
   - `path`는 대표 전류 경로(A→B, BJT는 C→E), `paths`는 다단자용(`CE`, `BE`, `primary`, `secondary` …). 같은 점을 연달아 넣지 않는다
     (`S.stream`이 길이 0 구간에서 NaN).
   - `S.layer` 안에서 그린 부품의 좌표는 그 레이어 기준이며, 그 부품의 `stream`/`energize`도 같은 레이어 안에서 부른다.
10. **부품 안 그리기 순서.** 한 부품은 `S.at` 시간창 안에서 몸통 → 기호 → 극성·글자 순으로 시간창을 비율로 나눠 그린다
    (부품 빌더가 각 획을 자기 소시간창으로 `ITEMS`에 등록, DOM 부모는 부품 그룹). 한 부품 0.35~0.7 s(승인된 속도).
11. **상태는 시간 키프레임.** `part.at(t, state)`는 즉시 바꾸는 함수가 아니라 키프레임 등록이다. `draw(t)`가 매 프레임 평가한다
    (seek-safe). 상태용 노드(스위치 팔 두 위치, 켜짐 글로우, 계기 바늘)는 미리 만들어 두고 t에 따라 보이기·회전만 바꾼다.
    스위치 전환과 바늘 이동은 0.25~0.4 s의 `sine.inOut`으로 움직인다.
12. **점선 버그 수정.** `prep()`은 `stroke-dasharray`가 이미 있는 선에는 덮어쓰지 않는다. 그런 선은 마스크 안의 실선으로 그리기 애니메이션을
    하고(점선이 펜으로 그려지듯), 짧은 점선(MOSFET 채널 등)은 처음부터 짧은 획 여러 개로 정의한다.

## 4. 부품 목록

공통 코어를 공유하는 변형은 옵션으로 합친다(함수 수를 줄여 사용법을 단순하게).

**A. 수동 소자** — `res`, `pot`(3단자, 와이퍼 `W`), `ldr`(저항 + 빛 화살표), `thermistor`(저항 + 사선), `cap`, `ecap`(+ 빨강),
`ind({core})`(반원 4개, `core: true`면 철심 두 줄), `xfmr`(4단자), `fuse`, `xtal`.

**B. 전원·기준** — `battery({cells: 1|2|…})`, `vdc`(원 + +/−), `vac`(원 + 사인), `isrc`, `gnd`, `vcc`, `port`.

**C. 반도체** — `diode({kind: 'std'|'led'|'zener'|'photo'})`(별칭 `led`, `zener` 유지; `led`는 `on` 상태),
`npn`/`pnp`, `nmos`/`pmos`(증가형), `opamp`, `chip`, `gate(type)`(`and or not nand nor xor`).

**D. 스위치·출력** — `sw({kind: 'spst'|'spdt'|'push'})`(열림/닫힘·위치를 키프레임으로), `relay`, `lamp`(on), `motor`, `speaker`.

**E. 계측기** — `meter({label: 'A'|'V'|'Ω'})`(별칭 `ammeter`, `voltmeter`), `dial`(반원 눈금 + 바늘, 값 키프레임; 3편 전압계를 정식 부품으로),
`scope`(파형 화면).

**F. 배선·구획** — `wire(pts)`, `route(pinA, pinB, {via})`(20 px 격자 위 직각 자동 연결), `dot`, `hop`(연결 안 된 교차),
`term`(빈 원), `curArrow`, `block(x, y, w, h, title)`(점선 구획: "입력단/증폭단", 레귤레이터 같은 블록).

**G. 물질 그림(이번 범위에 포함)** — `atom`, `electron`, `hole`, `ion`은 같은 정규 좌표계 + 고정 seed로 옮긴다(`lattice`는 `atom` 조합이라 자동으로 따라옴).
`band`, `hill`은 크기가 장면마다 달라지는 도형이라 그대로 두고 점선 버그 수정만 받는다.

**2단계(1단계 승인 뒤)** — 실물 그림(원통 건전지, 색띠 저항, 실물 LED, 전해 캔, TO-92, 브레드보드 조각),
`vcap`, `schottky`, `buzzer`.

## 5. 도감 시트와 검사

- `scripts/parts_sheet.py`: 도감 전용 런 페이지를 만들어 기존 스크린샷 경로로 PNG를 찍는다.
  **폰트 로드가 끝난 뒤, 모든 획이 그려진 시점(t = 런 길이)** 에서 찍고 검사한다(sketch.js:272-274의 폰트 후 재빌드 때문).
- **시트 1 — 도감:** 범주별(A~G) 격자. 부품마다 한국어 이름 + 함수명, 핀 이름, 상태(꺼짐/켜짐, 열림/닫힘, 바늘 두 위치).
- **시트 2 — 동일성:** 같은 부품을 0/90/180/270°, S/M/L, 다른 그리기 순서로 나란히. 자동 검사:
  - 부품 그룹 안 `<path d>` 문자열이 모든 변형에서 **완전히 같아야** 통과.
  - 글자는 월드 회전각 0°, 정해진 위치인지 확인.
  - 화면 선 굵기(`stroke-width × k`)가 크기와 상관없이 같은지 확인.
- **시트 3 — 회로 예:** 건전지–스위치–저항–LED, 트랜지스터 스위치, RC 충·방전(SPDT)을 도감 부품만으로 그리고 전류(`energize`·`stream`)도 켠다.
  1.5× 푸시 프레임도 한 장 찍어 라벨·핀이 영역(y 140–1395, x ≤ 960) 안인지 본다.

## 7. 호환

- 이미 공개한 PN 1~3편은 각 프로젝트 `work/`의 엔진 사본을 쓰므로 영향이 없다. 4편부터 새 키트를 받는다.
- 새 호출: `S.res(cx, cy, { rot, size, flip })`. **두 점 호출 `S.res(x1, y1, x2, y2, {s})`는 래퍼로 유지**한다
  (가운데 정규 몸통 + 양쪽 리드; 두 점 거리가 몸통보다 짧으면 `console.warn` 후 S 크기로). `res cap diode led`에 적용.
- `S.npn/pnp`는 `B C E inside`를 반환 최상위에도 그대로 둔다(`pins`와 같은 값). 핀 오프셋은 새 정규 모양을 따르므로,
  옛 공식으로 컬렉터 위치를 역산하는 `examples/gfx_sketch.py`는 반환 핀을 쓰도록 고친다.
- `S.battery(x, y, dir, s)`의 옛 시그니처도 래퍼로 유지(`{L, R}` 반환 포함).
- 스테이지 테마(유리 카드)는 범위 밖.

`non-scaling-stroke`가 카메라 확대 상쇄, `strokeDasharray` 덮어쓰기 버그(이미 있음), 0.8/1.4가 격자를 깸, 라벨 40 px가 44 px 규칙 위반,
`set` 상태의 seek-safe 모델 누락, `S.arrow` 이름 충돌, `gfx_sketch.py`의 npn 핀 역산, 작업 순서(코어 PoC 먼저), 린트는 JS 문자열 대상,
부품 통합(battery·ind·meter·diode·gate), SPDT·LDR·서미스터·route·block 추가, 물질 그림 범위 명시.
조정: 옛 npn 오프셋을 그대로 유지하라는 제안은 "같은 모양" 결정과 충돌하므로, 예제를 반환 핀을 쓰도록 고치는 쪽으로 바꿈.
`ohmmeter`는 `meter` 옵션으로 공짜라 남김. 배경 모눈은 외형 변경이라 사용자 결정으로 넘김.
